# 验收标准（DoD）- Swarm 自举式 MVP

## 总体验收

MVP 验收目标：证明“Swarm 能用自身范式构建并持续迭代 Swarm”。

必须满足：

1. 闭环可运行：`拆解 -> Skill -> 生成 -> 执行 -> 审核 -> 合并 -> 复盘`
2. Bee/Honey/Dance 均由 AI 生成
3. Skill-First 严格执行（无 Skill 不得直接生成执行产物）
4. 证据链完整且可审计

## A. 自举成功验收（新增核心）

- [ ] 至少 1 条真实功能链路由 Swarm 生产并合入本仓库
- [ ] 第二条功能点可复用同一方法成功复现（可在 M3 完成）

验收证据：
- PR/提交记录、功能运行结果、复盘纪要

## B. Skill-First 验收

- [ ] 核心技能可用：目标拆解、Bee/Honey/Dance 生成、代码审核、测试
- [ ] 执行链路先调用 Skill，再生成产物
- [ ] Skill 有版本号与变更记录
- [ ] Skill 回归测试可执行

验收证据：
- 技能目录、版本清单、调用日志、回归报告

## C. Bee 硬约束验收

- [ ] 支持等待和挂起
- [ ] 成功/异常均输出报告
- [ ] 不持久化 Honey（外部注入）
- [ ] 结果和报告通过 Dance 提交
- [ ] 附带测试类且覆盖率目标达标（100%）

## D. 可追踪与可审计

- [ ] 每次任务有唯一 ID
- [ ] 每个关键步骤有输入输出记录
- [ ] 异常链路可定位
- [ ] 关键流程可回放

## E. 记忆宫殿与成本

- [ ] 强相关记忆提取可用
- [ ] 无关召回噪声可控
- [ ] Token 对比统计可输出并展示优化趋势

## F. 发布验收

- [ ] 文档同步更新（README + Docs）
- [ ] 指标数据更新
- [ ] Demo 与 Retro 已完成

# Swarm 项目路线图（PM Draft）

## 北极星目标

用 Swarm 范式完成 Swarm 项目自身的持续交付，形成可复制的自举开发体系。

## M0：自举基线（第 1 周）

目标：建立“用 Swarm 开发 Swarm”的规则与证据链。

交付：
- 自举式 MVP 定义（本仓库即样板场景）
- Skill 命名、版本、输入输出规范
- 证据留存规范（调用日志/审核记录/测试报告）

完成标准：
- 团队对 Skill-First 和 Beekeeping 边界达成一致

## M1：首条自举链路跑通（第 2-4 周）

目标：产出第一个“由 Swarm 生产并合入 Swarm”的功能点。

交付：
- 目标拆解 Skill + 生成 Skill 链路
- Bee/Honey/Dance 生成与 Hive 执行
- 成功/异常报告模板
- 审核通过并合并到主干

完成标准：
- 有完整证据链
- 产物可回放、可复盘

## M2：稳定性与质量门禁（第 5-8 周）

目标：让自举链路从“能跑”变“稳定可重复”。

交付：
- Skill 回归测试
- Bee 等待/挂起能力稳定
- 覆盖率门禁（目标 100%）
- Token 成本看板 + 记忆宫殿召回优化

完成标准：
- 连续多次迭代稳定交付
- 指标出现可量化改善

## M3：复制到第二功能链路（第 9-12 周）

目标：证明该范式不是一次性成功。

交付：
- 第二条功能链路按同流程落地
- Skill 复用率统计
- 对外案例材料（过程、指标、结果）

完成标准：
- 第二条链路复用首条链路的技能体系并成功交付

## Go/No-Go 闸门

- M1：是否真实完成首条自举交付
- M2：是否达到稳定和质量门禁
- M3：是否可在第二链路复用并成功
